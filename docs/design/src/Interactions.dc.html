WHERE TOASTS COME FROM
v1 derives them from the event stream paddock already has: pane.agent_status_changed (blocked = needs input, working to idle/done = finished) and pane.agent_detected. herdr's own notification.show traffic is not observable on the api socket today (no notification event kind exists), so third-party toasts sent to herdr stay in herdr; a herdr-side "notification.shown" event is the upstream ask that would let paddock mirror them 1:1.
QUIET RULES
No toast for the focused pane (you are already looking at it). Status flaps within 2s coalesce. Toasts never stack more than 3 deep; older ones collapse into a "+2 more" pill. All of it lives on the same bottom-toast surface vocabulary as drag rejections, positioned top-right for attention vs bottom for transient notices.
